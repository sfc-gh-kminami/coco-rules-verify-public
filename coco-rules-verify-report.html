判定方法

検出CLI ログ ~/.snowflake/cortex/logs/coco.log の coco.instructions（Found N project instruction files）と coco.systemReminders（Loading N instruction file(s)）を session_id で照合
注入各ファイルにランダムな 12 文字の VERIFY-ID を記載。ツールを全てブロックした新規セッション（cortex exec）で列挙させる。ツール結果経由で出た ID は除外
遵守ファイルごとに固有の末尾タグ [TAG-xx] や言語指定を置き、出力から機械判定
強制ダミーの secret.txt／out.txt が実行後に変わったかで判定。hook 側の呼び出しログと sha256 も記録
分かったこと: CLI の検出状況は coco.log の coco.instructions 行で確認できます（要件 U-02 の回答）。hook の読み込みは Loaded hooks from project settings at <path> の行で分かります。

ハーネスの注意点（再現する人向け）

  • cortex exec は既定で全ツールを拒否します（headless mode requires --allowed-tools）。
  • --allowed は可変長引数で、後ろのメッセージを巻き込むことがあります。--allowed read --allowed write … -w <dir> "<msg>" の順に並べると回避できます。
  • cortex exec --cloud では --allowed を付けてもツールが自動拒否されました。また、注入されたのはローカルの AGENTS.md でした（1試行）。
  • 複数ターンは cortex --session-id <id> → cortex -r <id> -p で継続できます。-p は stdin を閉じないと止まったままになります。
  • 並列実行するとメモリ不足とみられるプロセス強制終了（rc=-9）が起き、空回答になります。今回は無効として扱いました。

7. 推奨構成（CLI を前提とした場合）

用途推奨理由
チーム共有gitルートに AGENTS.md を 1 つ置く。CLAUDE.md を併用するなら内容を重複させないDesktop・CLI のどちらでも確実に読まれる。複数形式は全部連結されるので、重複するとトークンの無駄と矛盾の元になる
モノレポルートに共通事項の AGENTS.md、各パッケージに個別の AGENTS.md。CLI はパッケージを -w に指定して起動作業ディレクトリ〜gitルートの全階層が注入される。下位ディレクトリは遅延読込されない
個人~/.snowflake/cortex/AGENTS.mdCLI と Desktop で共有の主保存先（docs）。競合時はワークスペースが勝つ
条件付きCLI では .mdc / .claude/rules / applyTo に頼らない。手順として必要なら skills に分けるCLI では読まれない。Desktop で効くかは未検証
強制.cortex/settings.json の PreToolUse hook（exit 2）、CI では --allowed / --blocked5/5 で決定的にブロックできた。指示文は従っただけで保証はない。matcher は大文字小文字の両方に一致させる（例 [Bb]ash、(?i) は未検証）と安全
使わない方がよいSNOWFLAKE.md、ワークスペースの .snowflake/cortex/settings.json（hooks）CLI では効かなかった
